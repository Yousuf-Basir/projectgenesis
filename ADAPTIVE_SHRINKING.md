# Adaptive terminal reclamation — 2026-10-23

Implemented as an experimental switch, disabled by default after an unfavorable first integration screen. Enable through `ReincarnationController({ adaptiveShrinkingEnabled: true })`. API diagnostics are `bonding.adaptiveShrinking` with configuration, reclaimed count, recovered energy and conversion loss.

Each component records total living member energy, internal bond reserves and component reserve. After at least eight observations, exponentially smoothed net decline (0.2 current/0.8 prior) estimates remaining operating ticks. If the estimate is below 30 ticks and a member is below the support threshold, one terminal member can be reclaimed. A degree-one member with low node trace is preferred. Closed cores are not dismantled; at least three members must remain. Surviving members receive an 80-age-tick cooldown shared across component members, preventing repeated removal when a key changes. History resets when membership changes or the world resets.

Up to 65% of the terminal member's stored energy plus the removed edge's reserve goes to its adjacent neighbour, limited by recipient capacity. The remainder is an explicit reclamation loss. The removed member's energy is zeroed before normal death processing, preventing a second residue payout. The component's existing reserve is transferred to the new membership key without duplication. No energy comes from topology or node count alone.

This first implementation forecasts shortage; it does not predict future gates, mutate the reclamation policy, or reduce movement as a new action. Existing support mechanisms continue to operate. Current forecast can respond too readily to short fluctuations and node trace is only an approximate contribution measure.

Validation: `node test/adaptive-shrinking.mjs` verifies waiting for history, terminal-only removal, closed-core retention, energy conservation with conversion loss, reserve retention and disabling. `node test/reincarnation-evolution.mjs` passes with shrinking enabled in the tested development version and confirms inheritance after a full 1,000-tick world. With shrinking: population 23, bonds 8, facets 2, deaths 83, gate completions 72. Earlier otherwise matching reference without shrinking: population 27, bonds 61, facets 98, deaths 60, completions 35. These single-seed endpoints do not show a survival benefit, despite more completed gate work. Therefore the experiment is retained for tuning but the live default stays off. Next work should record trigger histories and compare stricter forecasts against no shrinking over multiple seeds before promoting it.
